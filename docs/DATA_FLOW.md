# Data Flow Architecture

This document describes the lifecycle of data in the Previsão de Jogos platform, from raw collection to ML processing, model inference, and frontend consumption.

---

## 1. Pipeline Summary

The platform operates on two separate flows: the **Offline Ingestion & Training Pipeline** and the **Online Real-Time Inference Flow**.

```
[API-Football / martj42]
          ||
          \/ (ETL / build_final_dataset.py)
+------------------------------------+
|  Enriched Dataset (CSV / Parquet)  |
+------------------------------------+
          ||
          \/ (offline model training)
+------------------------------------+
|       Model Artifacts (.joblib)    |
+------------------------------------+
          ||
          \/ (real-time loaded into memory)
+------------------------------------+
|       Predictor Engine (Uvicorn)   | ===> [API JSON Response] ===> [Next.js UI]
+------------------------------------+
```

---

## 2. Ingestion & Transformation (Offline Pipeline)

### 2.1 Raw Data Sources
*   **Historical Base (martj42):** Contains results and pre-computed Elo ratings starting from 1872. This acts as the anchor dataset.
*   **API-Football:** Provides advanced box-score parameters (shots, possession, passes, fouls, corners, referee names, and yellow/red cards).

### 2.2 Processing & ETL
1.  **Parsing Raw Matches:** [build_history.py](file:///c:/Users/10341953440/Downloads/previsao-jogos/backend/build_history.py) reads raw API-Football json files (stored in `data/raw/` or SQLite `raw_cache`) and transforms them into flat rows for each team.
2.  **Dataset Construction:** [build_final_dataset.py](file:///c:/Users/10341953440/Downloads/previsao-jogos/backend/build_final_dataset.py) builds the final tabular dataset `international_features_enriched_apifootball.csv` (spanned to `features_enriched` table in the DB). It merges the matches, resolves team aliases, calculates point-in-time features (rolling averages, rest days, tournament ranks, and Elo ratings), and performs the **time-decay** and **style residualization**.

### 2.3 Style Residualization (Orthogonalization)
To capture team playstyle features (such as pressing intensity or card tendency) without duplicating signal already captured by the team Elo rating, the system uses [ortho_sinais.py](file:///c:/Users/10341953440/Downloads/previsao-jogos/backend/ortho_sinais.py).
It fits a regression of `Style_Feature ~ elo_diff` on training splits and extracts the residuals (`resid_*_style_*`). These residuals represent style markers independent of team strength.

## 3. Real-Time Inference Flow (Online Pipeline)

When a prediction is requested via the API:

```
[Frontend GET /api/analysis]
             ||
             \/
1. Load model weights & meta.json
2. Fetch pre-match features from `features_enriched` or live table `matches`
3. Execute `Predictor.build_row()`
4. Compute style residuals via `style_ortho_weights.joblib`
5. Generate marginal probability mass functions (PMFs)
6. Apply Isotonic O/U Calibrators
7. Return JSON response
```

### 3.1 Live Feature Builder
The backend [Predictor](file:///c:/Users/10341953440/Downloads/previsao-jogos/backend/predictor.py) loads models in memory from `/backend/model_artifacts/`. It dynamically reads pre-match parameters for both teams.

### 3.2 Post-Processing Calibration
For escanteios, cartões, and finalizações a gol, the PMFs generated by the models (Negative Binomial / Generalized Poisson) pass through isotonic calibration functions (`ou_calibrators.joblib`) to adjust probabilities in the extreme tail distributions.

### 3.3 Neon Egress Optimization (Aggregates)
To avoid loading heavy blobs from Neon database at runtime:
*   [precompute_aggregates.py](file:///c:/Users/10341953440/Downloads/previsao-jogos/backend/scripts/precompute_aggregates.py) runs a daily offline job to precompute statistics.
*   It saves small records in specialized tables (`referee_stats_agg`, `goal_timing_agg`, `competition_bench_agg`).
*   The endpoints load single pre-calculated rows, reducing data transfer egress by 90%.
